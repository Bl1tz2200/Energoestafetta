# Энергоэстафета — задача на 4 дня очного этапа

Выжимка из регламента. Полный текст — в PDF, приложения 1–4 не включены.

## Суть задания

Написать программу автономного взаимодействия **двух БВС (дронов)** с двумя
зарядными станциями (дронопортами) и доставки груза. Всё — автономно, без
ручного управления (кроме экстренного перехвата).

## Алгоритм полёта (то, что должна делать программа)

1. **БВС-1 и БВС-2** синхронно взлетают с разных площадок «Н» (индикация: жёлтый мигающий).
2. Асинхронно:
   - БВС-1 ищет зарядную станцию (индикация: красный).
   - БВС-2 летит в зону захвата груза (индикация: жёлтый мигающий).
3. БВС-1 садится на зарядную станцию по команде от станции, имитирует зарядку
   ~15 сек (красная мигающая лента), за 5 сек до взлёта — зелёная лента.
4. Пока БВС-1 заряжается, БВС-2 захватывает груз (сервопривод/магнит),
   включает красную ленту.
5. БВС-1 после зарядки и команды с клавиатуры возвращается на старт и садится
   (зелёный мигающий). БВС-2 взлетает с грузом и летит к зарядной станции
   (красная лента).
6. БВС-2 садится на зарядную станцию, имитирует зарядку (15 сек красная
   мигающая → за 5 сек до взлёта зелёная), сбрасывает груз.
7. **Зарядная станция сама (автономно, кодом)** определяет БВС по цвету
   светодиодной ленты и приглашает его на посадку/зарядку.
8. БВС-2 возвращается в точку взлёта и садится.

Полная таблица световой индикации по этапам — в самом регламенте (Таблица 1,
стр. 4–5).

## Формат работы на площадке (4 дня)

- Работаем по расписанию площадки, команда до 4 человек.
- **Тестовые попытки**: без ограничения по количеству, каждая ≤ 5 минут.
  Запись в очередь у организаторов; приоритет — у тех, кто ещё не летал.
- **Зачётная попытка**: одна, в конце 4-го дня, ≤ 15 минут. Разрешено
  неограниченное число перезапусков внутри неё; какой результат засчитывать —
  решает сама команда и озвучивает его в конце попытки.
- Перед первым тестовым полётом нужно продемонстрировать работу
  **KILL SWITCH** на каждом БВС.
- За 1 минуту до старта попытки — быть у полётной зоны; за 30 сек до конца —
  завершить полёты и покинуть зону (иначе штраф).
- После зачётной попытки — подписать оценочный лист (после подписи
  апелляция невозможна).

## Критерии оценки (баллы, кратко — полная таблица на стр. 5–6)

Начисляются по каждому этапу миссии: подключение к станции (2),
взлёт с метки (2), верная индикация на взлёте (1), полёт к грузу (2),
захват груза (4 за захват), полёт к станции/месту ожидания (1),
доставка груза (2), имитация зарядки (2), посадка в метке (2), станция сама
находит нужный БВС по цвету ленты (5, самый дорогой критерий), автономное
выключение моторов (1) — и т.д. для индикации на каждом этапе (по 1 баллу).

## Штрафы (стр. 6–7)

- Технические: касание станции бортом (−1), ножки за границей метки (−1 до 2
  ножек, −2 если больше), неверная/нерабочая индикация — балл просто не
  засчитывается.
- Техника безопасности: неисправное оборудование (−1), не выключенное
  оборудование при уходе (−1), напитки в открытой таре (−1), повреждённая
  изоляция (−3), БВС вне зоны с подключённым АКБ и пропеллерами (−3), полёт
  в автономном режиме при выключенном пульте (−3), просадка АКБ < 3.1В/ячейка
  (−1), заряд пульта < 40% (−1).
- **Дисквалификация**: полёты вне полётной зоны; полёты при людях внутри зоны.

## Требования к железу/ПО (стр. 7–9)

- Полётная зона: куб из ферм, ≥ 8×8×4 м, обтянут сеткой, две зарядные станции,
  поле Aruco-меток (7×7, размер метки 0.33 м, шаг 1 м, номера 0–48).
- Комплект на команду: 2 БВС, имитатор зарядной станции (Raspberry Pi +
  светодиодная лента + плата питания), 3 аккумулятора, 2 модуля захвата,
  зарядное устройство, инструменты, ноутбук, груз, роутер.
- ПО: BalenaEtcher, VMware Workstation Player, QGroundControl, прошивка
  полётного контроллера, образ ОС с Gazebo, RobboScratch, Zadig, Cfclient,
  Ubuntu 22.04.4 LTS, Python 3.8, OpenCV, Scratch 3 + EDU.ARD.

## Технические уточнения по дрону (Skyris Technic 6S)

Официальная документация: docs.skyris.ru/technic6S/. Это важно, потому что
она **не совпадает** с частью общего списка ПО из регламента (стр. 8–9) —
см. предупреждение в конце раздела.

- **Железо**: полётный контроллер **PX4**, бортовой компьютер —
  **Orange Pi 5 Pro**. Симулятор — **Gazebo** (нативно, в VM или на Apple
  Silicon), есть Rviz/RQT.
- **Стек — ROS 1 (rospy, не ROS 2!)**, пакет `technic` (форк экосистемы
  Clover) + MAVROS + pymavlink. Все примеры в документации — `rospy`,
  а не `rclpy`.
- **Автономный полёт (OFFBOARD)** — сервисы ROS:
  ```python
  rospy.init_node('flight')
  get_telemetry = rospy.ServiceProxy('get_telemetry', srv.GetTelemetry)
  navigate = rospy.ServiceProxy('navigate', srv.Navigate)
  land = rospy.ServiceProxy('land', Trigger)  # std_srvs.srv.Trigger

  navigate(x=0, y=0, z=1.5, speed=0.5, frame_id='body', auto_arm=True)  # взлёт
  navigate(x=5, y=0, z=3, speed=0.8)  # полёт в точку
  land()
  ```
  В «Примерах кода» есть готовые обёртки `navigate_wait()`, `land_wait()`,
  `wait_arrival()`, `get_distance()`, `get_distance_global()`.
- **Светодиодная лента** — сервисы `led/set_effect` (пакет `technic`,
  параметры `r,g,b` + опциональный `effect`: `fill`/`fade`/`flash`/`blink`/
  `rainbow`) и `led/set_leds` (пакет `led_msgs`, поштучно через
  `LEDState(index, r, g, b)`); число диодов — топик `led/state`.
- **Сервопривод/захват груза — НЕ через ROS.** Управляется напрямую системной
  утилитой `gpio` (WiringPi) на Orange Pi: `gpio mode <pin> pwm`, `gpio pwmr`,
  `gpio pwmc`, затем `gpio pwm <pin> <value>`, где value — «сырой» ШИМ-импульс
  (в примере 1000/1500/2000), а не угол 0–180°.
- **Камера** — топик `main_camera/image_raw` (`sensor_msgs/Image`, `bgr8`),
  кадр в OpenCV получается через `cv_bridge.CvBridge().imgmsg_to_cv2(msg,
  'bgr8')`.
- **ArUco-метки уже распознаются платформой из коробки**: пакет `aruco_pose`
  публикует топик `aruco_detect/markers` (`MarkerArray`) с полями `id`,
  `pose.pose.position`, `corners2d` — отдельно писать детектор ID/позиции не
  обязательно. Своя логика нужна только для **цвета** зарядной станции (его
  `aruco_pose` не определяет) и для привязки цвета к найденной метке.

**Важно — расхождение со списком ПО в регламенте (стр. 8–9).** Общий список
организаторов включает `Cfclient` (GCS для дронов Crazyflie) и
`RobboScratch`/`Scratch 3 + EDU.ARD` (обвязка для Arduino/Robbo) — это
инструменты для **другого** класса дронов, не для PX4/Orange Pi. Похоже,
регламент — общий шаблон на несколько дисциплин/моделей дронов сразу. Для
Skyris Technic 6S из этого списка реально нужны: BalenaEtcher (прошивка
образа Orange Pi), VMware + образ Gazebo, QGroundControl, Ubuntu, Python,
OpenCV; актуальность Zadig/Cfclient/RobboScratch стоит уточнить у
организаторов на месте в первый день, а не тратить на них время заранее.

## Что делать в ближайшие 4 дня (черновой план)

1. Развернуть/проверить ПО и прошивки на выданном железе (или своём, если
   соответствует моделям), поднять симулятор/подключение к реальным БВС.
   Убедиться, что на ноутбуке настроено окружение ROS 1 (rospy, `technic`,
   `led_msgs`, `aruco_pose`, `cv_bridge`) — не ROS 2.
2. Реализовать автономный взлёт с меток через сервисы `navigate`/`land`
   пакета `technic` и распознавание меток/станций: ID и позицию берём из
   готового топика `aruco_detect/markers` (`aruco_pose`), а цвет станции —
   своим HSV-детектором по кадру с `main_camera/image_raw`.
3. Реализовать логику связи БВС ↔ зарядная станция (запрос посадки, имитация
   зарядки с таймингами 15с/5с, автономное определение станцией нужного БВС
   по цвету ленты — это самый дорогой критерий, 5 баллов) через сервисы
   `led/set_effect` и `led/set_leds`.
4. Реализовать захват/сброс груза через утилиту `gpio` (WiringPi) на Orange
   Pi — подобрать `open_pulse`/`close_pulse` под конкретный сервопривод — и
   правильную световую индикацию на каждом этапе (таблица 1).
5. Собрать полный сценарий из 8 шагов (синхронный взлёт → асинхронные
   задачи → зарядка/захват → обмен ролями → финальная посадка).
6. Отладка через тестовые попытки (неограниченно, по 5 мин, в очереди),
   фиксировать проблемные места по каждому пункту критериев оценки.
7. Проверить технику безопасности (KILL SWITCH, заряд АКБ/пульта, изоляция,
   поведение вне зоны) — чтобы не терять баллы на штрафах.
8. В конце 4-го дня — зачётная попытка (15 мин, неограниченные рестарты
   внутри неё, но нужно явно объявить итоговый результат).
