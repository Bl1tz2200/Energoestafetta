# Энергоэстафета — зарядная станция

Ветка `charging-station`: **только** автономный контроллер зарядной станции
(дронопорта) и те модули, которые он использует. Полётные сценарии БВС-1/БВС-2,
диагностика, карта поля и общий план работ — на ветке `main`.

Станция закрывает шаг 7 алгоритма соревнования — «зарядная станция сама,
автономно, определяет БВС по цвету светодиодной ленты и приглашает его на
посадку/зарядку». Это самый дорогой критерий регламента (5 баллов) и пункт
2.1 плана работ.

## Структура ветки

```text
.
├── charging_station.py        # запуск на Raspberry Pi станции
├── README.md
└── lib/
    ├── led_interface.py       # set_led(pattern, color) и бэкенды ленты
    ├── station_protocol.py    # таблица сигналов БВС↔станция
    └── energy_relay_vision.py # StationVision: HSV-детектор цвета (+ ArUco)
```

`charging_station.py` берёт модули из `lib/` по пути `--repo-root`, который по
умолчанию равен папке самого файла — то есть достаточно склонировать ветку
целиком и запускать скрипт из её корня. Если файл лежит отдельно от `lib/`,
путь к чекауту нужно указать явно: `--repo-root /путь/к/Energoestafetta`.

## Как работает

Ядро — конечный автомат `run_station()`; все внешние зависимости (кадр,
детектор, лента, время) передаются в него явными аргументами, поэтому логика
проверяется самотестом без камеры и Raspberry Pi.

1. Кадр с камеры → `StationVision.detect()` → список цветовых пятен в кадре.
2. `select_drone()` отбрасывает пятна не того цвета, с уверенностью ниже
   `--min-confidence` и слишком мелкие/крупные по доле кадра
   (`--min-area-ratio`/`--max-area-ratio`).
3. Цвет должен подтвердиться `--required-frames` кадров **подряд** — разрыв
   серии сбрасывает счётчик, случайный блик приглашения не вызывает.
4. Станция включает зелёную ленту — это и есть приглашение на посадку
   (`station_protocol.Signal.LANDING_GRANTED`).
5. Держит её `--grant-hold` секунд, затем гасит.
6. Новое приглашение разрешается только после `--reset-frames` кадров подряд
   **без** цвета БВС в кадре — чтобы станция не позвала тот же борт повторно.

Сигналы (`lib/station_protocol.py`): отдельного сетевого канала между Orange Pi
борта и Raspberry Pi станции в этой раскладке нет, обмен идёт только через
цвет, который видят камеры друг друга. БВС ищет станцию с красной лентой
(`LANDING_REQUEST` = `red` — по ней станция его и опознаёт), станция отвечает
зелёной (`LANDING_GRANTED` = `green`), борт читает её своей камерой.

ROS на станции не нужен: Raspberry Pi — самостоятельный Python-процесс, без
`rospy`/`technic`/MAVROS.

## Требования

```bash
pip install opencv-contrib-python numpy   # камера и детектор цвета
pip install rpi-ws281x                    # только для --led-backend ws281x
```

Python 3.8+ (регламент требует 3.8). Управление лентой WS281x через GPIO
требует запуска от `sudo`. Для `--self-test` не нужно ничего, кроме Python:
OpenCV подгружается только на боевом пути.

## Запуск

Проверка логики без камеры и Raspberry Pi (можно прямо на ноутбуке):

```bash
python3 charging_station.py --self-test
```

Сухой прогон на площадке — реальная камера, но лента не трогается, команды
печатаются в консоль; `--once` завершает работу после первого приглашения:

```bash
python3 charging_station.py --camera 0 --drone-colors red \
    --led-backend console --once
```

Боевой запуск с лентой WS281x на GPIO18:

```bash
sudo python3 charging_station.py --camera 0 --drone-colors red \
    --led-backend ws281x --led-pin 18 --led-count 12 --brightness 128
```

Остановка — Ctrl+C: `SIGINT`/`SIGTERM` обрабатываются штатно, лента гасится,
камера освобождается.

## Аргументы

| Флаг | По умолчанию | Зачем |
| --- | --- | --- |
| `--repo-root` | папка скрипта | где искать `lib/` с модулями репозитория |
| `--camera` | `0` | индекс камеры (Raspberry Pi/USB) |
| `--width`, `--height` | `0` (как отдаёт камера) | уменьшить кадр, если частота проседает |
| `--camera-warmup` | `1.0` | пауза после открытия камеры, с |
| `--drone-colors` | `red` | цвета ленты БВС через запятую: `red,green,yellow,blue` |
| `--required-frames` | `5` | сколько кадров подряд цвет должен подтвердиться |
| `--reset-frames` | `10` | сколько кадров подряд БВС должен отсутствовать до нового приглашения |
| `--min-confidence` | `0.45` | ниже — пятно не считается лентой БВС |
| `--min-area-ratio` | `0.003` | минимальная доля кадра, которую занимает лента |
| `--max-area-ratio` | `0.35` | максимальная доля кадра (отсекает фон/засветку) |
| `--poll-interval` | `0.05` | пауза между кадрами, с |
| `--grant-hold` | `15.0` | сколько держать зелёное приглашение, с |
| `--once` | выкл. | выйти после первого приглашения (для тестов) |
| `--dictionary` | `DICT_4X4_50` | словарь `cv2.aruco`, должен совпадать с настройкой поля |
| `--led-backend` | `console` | `console` — печать команд, `ws281x` — физическая лента |
| `--led-count`, `--led-pin` | `12`, `18` | параметры ленты станции |
| `--brightness` | `128` | яркость ленты, 0..255 |
| `--self-test` | выкл. | проверить конечный автомат без камеры и Raspberry Pi |

## Вывод

Каждое событие — одна JSON-строка: читается глазами и складывается в лог
попытки без дополнительного разбора.

```text
{"event":"station_started","time":...,"camera":0,"expected_colors":["red"],"led_backend":"ws281x"}
{"event":"drone_confirmed","time":...,"drone_color":"red","confidence":0.91}
{"event":"landing_granted","time":...,"drone_color":"red","confidence":0.91,"frame_ratio":0.021,"bbox":[...]}
{"event":"station_ready","time":...,"grants":1}
{"event":"station_stopped","time":...}
```

## Что настроить на площадке

- **`--drone-colors`** — конкретный цвет ленты БВС назначают эксперты перед
  попыткой. Поддерживаются `red`/`green`/`yellow`/`blue`; диапазоны HSV лежат
  в `DRONE_COLOR_RANGES` (`charging_station.py`), при другом цвете диапазон
  добавляется туда.
- **Пороги детектора** (`--min-confidence`, `--min-area-ratio`,
  `--max-area-ratio`) — под освещение зала и расстояние, с которого станция
  видит подлетающий борт. Слишком широко — станция среагирует на любую
  красную куртку в кадре; слишком узко — не увидит сам борт. Подбирать сухим
  прогоном (`--led-backend console`), глядя на `confidence`/`frame_ratio` в
  выводе.
- **`--required-frames`/`--reset-frames`** — при `--poll-interval 0.05` пять
  кадров ≈ 0.25 с подтверждения.
- **`--grant-hold`** — 15 с по регламенту (значение по умолчанию); согласовать
  с таймингом имитации зарядки на борту.
- **Собственная лента станции в кадре.** Если экспертам угодно назначить БВС
  зелёный цвет, станция может принять за борт свою же зелёную ленту —
  проверить угол обзора камеры и при необходимости увести ленту из кадра.
- **`--led-pin`/`--led-count`/`--brightness`** — под физическую ленту станции.

## Чего станция пока не делает

- Не проверяет, что борт действительно сел и «зарядился» — приглашение
  снимается по таймеру `--grant-hold`, а не по факту посадки.
- Не подключена к полётным сценариям: ожидание зелёного сигнала на стороне
  БВС (`station_protocol.wait_for_signal(Signal.LANDING_GRANTED, ...)`) в
  `bvs1_flight.py`/`bvs2_flight.py` на ветке `main` ещё не встроено — это
  Приоритет 5 плана.

## Проверка без станции (self-test)

```bash
python3 charging_station.py --self-test
python3 lib/led_interface.py --self-test
python3 lib/station_protocol.py --self-test
python3 lib/energy_relay_vision.py --self-test   # нужны opencv-contrib-python/numpy
```

Это не заменяет прогон на реальной станции — проверяется только логика
(фильтрация кадров, серии подтверждения, цвета протокола, паттерны ленты).
