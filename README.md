# Энергоэстафета — Архипелаг 2026

Весь код команды: два дрона Skyris Technic 6S (PX4 + Orange Pi 5 Pro, ROS 1/rospy)
и зарядная станция на Raspberry Pi. Задание и регламент — [docs/TASK.md](docs/TASK.md),
план работ — [docs/PLAN.md](docs/PLAN.md).

Ветка `main` — сборка всего проекта. Работа идёт в ветках: `UAV1` (первый дрон),
`UAV2` (второй), `charging-station` (станция).

## Быстрый запуск

Три машины, три команды. Порядок: сначала станция, потом дроны.

```bash
# 1. СТАНЦИЯ (Raspberry Pi, из корня репозитория)
sudo python3 charging_station.py --camera 0 --drone-colors red \
    --led-backend ws281x --drone uav1=192.168.0.11 --drone uav2=192.168.0.12

# 2. БВС-1 (Orange Pi, дрон стоит на площадке «Н», метка 48)
python3 uav1_flight.py --station 192.168.0.21

# 3. БВС-2 (свой Orange Pi, своя площадка «Н»)
python3 fly_uav2.py
```

Адреса — свои, из настроек роутера. Пульты с KILL SWITCH в руках у обоих
операторов: аварийный перехват возможен только с них.

**Перед первым запуском в день соревнования** — проверка без моторов, займёт
минуту:

```bash
python3 uav1_flight.py --check --station 192.168.0.21   # карта, сводка, связь
python3 charging_station.py --self-test                 # логика станции и обмен
diff <(grep -v '^#' config/field_map.txt) <(grep -v '^#' ~/technic_ws/src/technic/aruco_pose/map/map1.txt)
```

Последняя строка важнее остальных: если карта на платформе не совпадает с нашей,
дрон считает место по одной раскладке, а летит по другой — и уверенно уходит не
туда. Это самая частая причина сорванных попыток.

## Что где лежит

```text
uav1_flight.py         БВС-1: взлёт, зарядка, возврат — полный сценарий с регламентом
fly_uav2.py            БВС-2: груз, своя станция (метка 37), возврат
charging_station.py    станция: опознание борта по цвету ленты + связь по UDP
config/field_map.txt   карта поля 7x7, формат aruco_pose
lib/                   модули станции и БВС-2
docs/                  задание, регламент, план работ
CLAUDE.md              инструкции для Claude Code
```

`uav1_flight.py` ничего из `lib/` не импортирует — он самодостаточен и возится на
борт одним файлом. `fly_uav2.py` тянет `lib/marker_nav.py`, `charging_station.py`
— остальные модули `lib/`.

| Кто | Куда летит | Метка старта | Что делает на станции |
| --- | --- | --- | --- |
| БВС-1 | станция на метке **5** | 48 | просит посадку по UDP, заряжается 15 с, ждёт Enter, возвращается |
| БВС-2 | груз на метке **0**, станция на метке **37** | своя «Н» | садится на груз (без захвата), потом на свою станцию |

У каждого дрона **своя** зарядная станция — это разные кубы, не одна на двоих.

## Связь борта со станцией

Одноранговый UDP, порт 5801, JSON-датаграммы. Сервера нет: обе стороны слушают
один порт и шлют прямо на IP собеседника, поэтому порядок включения не важен и
выключенная сторона ничего не вешает.

```text
БВС   -> станция   landing_request   прошу посадку (повтор, пока вишу над кубом)
станция -> БВС     landing_granted   садись
БВС   -> станция   landed / departed сел / улетел, площадка свободна
```

**Опознание борта идёт по IP**, поэтому адреса нужны с обеих сторон: станции —
`--drone uav1=<IP дрона>`, дрону — `--station <IP станции>`. Датаграмма с чужого
адреса отбрасывается молча.

**Сеть не подменяет цвет.** Регламент требует, чтобы станция сама находила нужный
борт по ленте (5 баллов), и приглашение зажигается по цвету даже при мёртвой
сети. UDP добавляет адресность и обратную связь, а не заменяет камеру.

Проверка связи без камеры и полёта:

```bash
python3 lib/station_link.py --id station1 --peer uav1=192.168.0.11 --listen
python3 lib/station_link.py --id uav1 --peer station1=192.168.0.21 --hello
```

Не проходит при верных адресах — почти всегда **изоляция клиентов** на роутере.

## Подробности по частям

- **БВС-1** — ветка `UAV1`, там README с полным разбором: соблюдение регламента,
  таблица отказов, VPE и как его чинить, перенос кода на борт.

  настраивать на площадке.
- **БВС-2** — ветка `UAV2`.

## Что не проверено в воздухе

- **Связь со станцией** прогонялась только самотестами и на loopback-сокетах;
  на площадке между двумя устройствами не проверялась.
- **Новые шаги регламента у БВС-1** (запрос посадки, ожидание Enter, дизарм) в
  полёте не проверялись. Летала версия без них: взлёт, перелёт по `aruco_map`,
  зарядка, возврат, посадка — 2026-08-02.
- **Посадка на куб 80 см** делается штатным `land()`; поведение на приподнятой
  поверхности документацией Skyris не описано.
- **Поворот меток `rot_z = -1.5708`** в карте выведен из описания «повёрнуты на
  90° вправо», а не измерен. Знак проверяется на борту по `/aruco_map/pose`; не
  сошлось — `1.5708` во всех строках.
- **Захвата груза у БВС-2 нет** — на метке груза он садится и ждёт.
